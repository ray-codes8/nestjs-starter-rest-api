# Nihongo Quiz — Design

Date: 2026-10-13
Status: approved in brainstorming, pending written-spec review

## Goal

A pet project for learning Japanese (JLPT N5/N4, structured after Minna no Nihongo) with
Anki-like spaced repetition, delivered as multiple-choice quizzes.

- Frontend: new React SPA consuming the existing NestJS starter API (auth, users).
- Backend: new modules added to this repo as backend practice.
- Hard constraint: a demo to the CTO on 2026-10-14. A polished end-to-end vertical slice
  beats breadth. Scope is cut from the end of the build order (see below) if time runs out.

## Content source

- Vocabulary: open JLPT N5/N4 word lists (Jonathan Waller, tanos.co.uk, CC-BY), converted to
  a JSON seed file committed to this repo. Attribution in the seed file header and README.
- The schema has a nullable `lesson` column so Minna no Nihongo lesson mapping (lessons 1–25 ≈ N5,
  26–50 ≈ N4) can be added later by importing a user-authored list.
- No textbook text, dialogues or exercises are reproduced.
- Verb conjugation questions are generated by code from the seeded verbs.

## Architecture

```
nihongo-web (React SPA) ──JWT──▶ NestJS API ──▶ PostgreSQL
                                  ├ auth, user   (existing)
                                  ├ vocabulary   (new)
                                  ├ quiz         (new)
                                  └ progress     (new)
```

- Backend: this repo, branch `feature/nihongo-quiz`. New modules follow the layout of
  `src/article` (controllers / services / repositories / dtos / entities).
- Frontend: separate project `../nihongo-web` (sibling folder, own git repo).

## Data model

`words`
- id (PK), kanji (nullable), kana, romaji, meaningEn, meaningRu (nullable)
- partOfSpeech: enum `noun | verb | i-adj | na-adj | adverb | other`
- verbGroup: enum `1 | 2 | 3`, nullable (verbs only)
- level: enum `N5 | N4`
- lesson: int, nullable

`user_word_progress`
- id (PK), user (FK users), word (FK words), unique (user, word)
- box: int 1–5, nextReviewAt: timestamp, correctCount, wrongCount

`answer_log`
- id (PK), user (FK), word (FK), quizType: enum `vocabulary | verb`, isCorrect, createdAt

Tables are created by a TypeORM migration. The seed runs as `npm run seed:words`, a standalone
script modeled on `src/cli.ts` that upserts words by (kana, kanji, level) so it can be re-run safely.

## Spaced repetition (Leitner)

- 5 boxes. Intervals: box 1 → 1 day, 2 → 2, 3 → 4, 4 → 8, 5 → 16.
- Correct: box = min(box + 1, 5). Wrong: box = 1. nextReviewAt = now + interval(box).
- First answer on a word creates its progress row (starting from box 1 before applying the rule).
- "Learned" = box ≥ 4.
- Implemented as a pure function `applyAnswer(progress, isCorrect, now)` for easy testing.
- SM-2 is a roadmap item, not in scope.

## Verb conjugation

Pure function `conjugate(word, form)` for forms `masu | te | nai | ta`.
Handles group 1 (う/つ/る→って, む/ぶ/ぬ→んで, く→いて, ぐ→いで, す→して; 行く→行って),
group 2 (drop る) and group 3 (する, 来る / くる). Applies to the kana and to the kanji form.

Distractors are plausible wrong conjugations (e.g. 書く te: 書いて ✓, 書って, 書きて, 書くて),
produced by applying other groups' rules or common mistakes, de-duplicated against the correct answer.
If fewer than 3 distinct distractors are produced, fill up with the correct form of a different verb.

## API

All endpoints require `JwtAuthGuard`, use `BaseApiResponse`, and are documented in Swagger.

| Method | Path | Description |
|---|---|---|
| GET | `/vocabulary?level&limit&offset` | Paginated word list (`PaginationParamsDto`) |
| GET | `/quiz/vocabulary?level&count` | Questions: due-today words first, then new words, then random fill |
| GET | `/quiz/verbs?level&count` | Verb + target form + 4 options |
| POST | `/quiz/answer` | Check the answer, update progress, write answer_log |
| GET | `/progress/summary?level` | `{ total, learned, dueToday, streakDays, accuracy7d }` |

- `count`: 1–20, default 10. `level`: `N5 | N4`.
- A vocabulary question is `{ wordId, kanji, kana, options: string[4] }`. Options are English meanings.
  Distractors are drawn from the same level and part of speech. The correct answer is not sent.
- A verb question is `{ wordId, kanji, kana, form, options: string[4] }`.
- The answer body is `{ quizType, wordId, answer, form? }`. The response is
  `{ isCorrect, correctAnswer, newBox, nextReviewAt }`.
- `streakDays`: consecutive calendar days (server time) ending today or yesterday with ≥1 answer.
- `accuracy7d`: correct / total over the last 7 days of answer_log, or null if there are none.

## Frontend (`nihongo-web`)

Stack: React + Vite + TypeScript + Tailwind + shadcn/ui, React Router, TanStack Query, axios,
sonner for toasts. Fonts: Noto Sans JP (Japanese) and Inter.
Look: warm paper-toned light theme with a vermilion (朱色) accent; dark theme through shadcn.

Auth: tokens stored in localStorage. An axios interceptor handles 401 by calling
`/auth/refresh-token` once and retrying the request. If the refresh fails, the user is sent to login.

Screens:
1. Login / Register: centered card with a Japanese motif, form validation.
2. Dashboard: N5/N4 switch, four stat cards (learned / due today / streak / accuracy),
   "Vocabulary" and "Verbs" start buttons.
3. Quiz: progress bar, large word with furigana, 4 option buttons (keys 1–4),
   green/red feedback with a short animation, auto-advance after ~1s.
4. Result: score, list of mistakes with correct answers, "Again" / "Dashboard".
5. (Stretch) Dictionary: searchable word table with box badge.

States: skeletons while loading, error toasts, and an empty state when a level has no words
("run seed").

## Error handling

- DTO validation with class-validator (enums, count range).
- An unknown wordId returns 404 via the existing exception classes.
- A repeated answer submission counts as another attempt. No idempotency handling.

## Testing

- Unit: `conjugate` (table-driven, all groups + exceptions), `applyAnswer` (Leitner rules),
  `QuizService` (4 unique options containing the correct one, distractors share part of speech).
- e2e: register → login → get quiz → answer → summary reflects the answer.
- Frontend: manual run-through of the full flow only (demo constraint).

## Build order (cut from the bottom if needed)

2. Backend: quiz + progress modules, verified in Swagger.
3. Frontend: scaffold, auth, dashboard.
4. Frontend: vocabulary quiz + result screen. ← minimum viable demo
5. Frontend: verb quiz.
6. Polish: animations, dark theme, dictionary screen.

## Out of scope (roadmap slide)

lists, SM-2, AI-generated exercises, admin content UI, frontend unit tests.
